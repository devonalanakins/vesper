# Vesper security policy

Early-stage public offline research code; no live accounts, banking, trading or broker integrations exist here.

Use a private maintainer channel or GitHub private vulnerability reporting (if enabled) for security reports. Do not open public issues containing credentials, vulnerabilities or identifiable financial information.

Future read-only connections require audited server-side owner/account authorization, data provenance, secure storage, least privilege and privacy boundaries. Future execution and treasury endpoints require distinct explicit owner approval, independent review, idempotency, kill switches, recovery drills and audited authorization. No synthetic UI test or green CI grants these permissions.
